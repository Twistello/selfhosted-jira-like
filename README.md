# Forgeboard

Self-hosted трекер для небольшой команды: TypeScript, React, NestJS и PostgreSQL.

**Статус: рабочая частичная реализация исходного ТЗ, не завершённый продукт.** Реализованы аутентификация/TOTP, проектные права, задачи, workflow, спринты с историческими снимками, wiki, ручной учёт времени и часть GitLab CE. WebAuthn, SSO, вложения, полный набор аналитики, автоматизация и другие обязательные разделы ещё не готовы. См. [матрицу приёмки](docs/acceptance-matrix.md), [исходное ТЗ](docs/requirements.md) и [checkpoint](docs/checkpoint.md).

## Локальный запуск

Нужны Node.js 22+ (проверено на 24.14.0), npm и PostgreSQL 15+. Внешний SaaS и Redis не требуются. Фоновые задания исполняются тем же процессом через PostgreSQL.

```sh
npm ci
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Сохраните полученный ключ в `APP_ENCRYPTION_KEY` внутри `.env`. Укажите `DATABASE_URL` своей отдельной БД и `PUBLIC_URL=http://127.0.0.1:3000`. БД нужно предварительно создать; приложение создаёт таблицы, но не саму БД.

```sh
npm run migrate
npm run build
npm start
```

Откройте [локальное приложение](http://127.0.0.1:3000). Первый пользователь создаёт владельца со своим паролем длиной минимум 12 символов. Публичного стандартного пароля и свободной регистрации нет. Для разработки отдельно запустите `npm run dev` и `npm run web`; frontend доступен на порту 5173.

## Production Compose

Задайте в `.env` `DOMAIN`, случайный URL-safe `POSTGRES_PASSWORD`, `APP_ENCRYPTION_KEY` и, при необходимости, `INTEGRATION_ALLOWED_ORIGINS`. Домен должен указывать на сервер, порты 80/443 должны быть доступны Caddy для HTTPS.

```sh
docker compose up -d --build
```

БД не публикует порт наружу; PostgreSQL использует постоянный volume. Caddy получает HTTPS-сертификат и проксирует приложение. Секрет шифрования сохраните отдельно от БД: без него нельзя расшифровать TOTP и интеграционные токены. Контейнеры в текущей Windows-среде не запускались, потому что Docker daemon недоступен; подготовка Compose не равна проверенному развёртыванию.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run check:secrets
npm audit --omit=dev
npx playwright install chromium
npm run test:e2e
```

`npm test` требует настоящую PostgreSQL и права создавать схемы. Тест резервного копирования также требует права создавать/удалять отдельные тестовые БД и PostgreSQL client tools (`PG_BIN` для каталога binaries). Playwright по умолчанию использует отдельную БД `forgeboard_e2e`; создайте её или задайте `E2E_DATABASE_URL`. Каждый браузерный запуск создаёт новую схему. Не направляйте тесты в рабочую БД. E2E schemas остаются в тестовой БД для диагностики; саму тестовую БД можно пересоздавать отдельно.

OpenAPI доступен на `/api/docs`, JSON на `/api/docs-json`; текущая автогенерация перечисляет маршруты, но подробные DTO-схемы ещё не описаны. Health `/api/v1/health`, readiness `/api/v1/ready`. Объектные операции требуют cookie-сессию; изменяющие запросы с cookie также требуют соответствующий `Origin`.

## GitLab CE

Администратор добавляет точный origin GitLab в `INTEGRATION_ALLOWED_ORIGINS`, перезапускает приложение, создаёт подключение с токеном, проверяет соединение и выбирает репозиторий. Создание webhook — отдельное явное действие. По умолчанию данные разработки видят только администраторы; публикация участникам проекта требует явного выбора. [Настройка, контракты и ограничения](docs/gitlab.md).
